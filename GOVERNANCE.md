# Governance

HAIDAA currently uses a lightweight maintainer-led model. Protocol discussion can be public. Major changes should be proposed through [RFCs](docs/rfcs/README.md); maintainers retain authority over the canonical protocol and hosted service. Discussion does not promise acceptance or deployment.

Public contributions focus on protocol, schemas, integration and documentation. Production implementation and security-sensitive controls are maintained privately. Security reports use the private channel in [SECURITY.md](SECURITY.md).

Open-source code and network membership are separate concepts. Running compatible software does not automatically confer trust or write authority in the canonical HAIDAA network. A future architecture may allow independent compatible nodes while the canonical network applies explicit identity, provenance, trust and federation rules. Federation is not implemented today.
